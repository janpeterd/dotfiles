## Environment and scope

Pi 0.84.3, Python 3 and Node 26.8.1 on Linux. Implementation fixtures cover Python and TypeScript runtime behavior. No TypeScript compiler proof, production Geoflow navigation benchmark, or cross-family inference is claimed. Exact `openai-codex/gpt-5.6-sol` and `openai-codex/gpt-6-astra` are the only models in the comparison. Astra is registered through the local evaluation extension, without changing global Pi configuration.

## Infrastructure findings

The initial atomic-settlement campaign is exploratory. Its early trials used a superseded Astra adapter that could leave the process alive after an answer. Timeouts and incomplete cells are infrastructure failures; completed source can inform investigation but the campaign does not establish a controlled promotion comparison.

The first shuffled batches exposed inherited stdin: candidate processes could consume the remaining launch schedule. Regression tests reproduced the missing cells. Both the launcher and child process now use null stdin. Completed cells retain their original provenance; missing cells are scheduled separately with the same frozen case, skill, model and thinking level. Original incomplete campaign records remain intact. Updating the launcher while two earlier shells were still reading it also caused shell parse errors; those interrupted batches are not counted as complete. Later runs use the frozen corrected scripts.

An earlier Anthropic attempt failed before an answer because authentication had expired. It is excluded. The subsequent explicit provider prohibition is enforced before launch, including proxy aliases. No authentication retry is planned.

## Reviewer calibration

An independent reviewer, without candidate skills or grading anchors, compared behaviorally correct settlement and validation pairs. It identified the actual distributed check/write knowledge in settlement B and the shared ordering/pattern policy in validation B. It did not invent duplicated balances, partial commits or public configuration flags. It allowed ties for changes already supported by the private validation configuration. A same-reviewer reversed-order check preserved its reasons; that is a consistency check, not independent statistical blinding.

## Initial blinded findings

Four completed derived-view outputs all passed external oracles. The reviewer tied their actual code quality on the specified contract. Three scored 6/6 on the explanation/design rubric; one prior Sol output scored 5/6 for an unexplained move from lazy snapshot work to eager work at every commit. The proposed Sol output also made an overbroad claim that private batch extraction would necessarily divide invariants. That claim was qualified in the review, not treated as a demonstrated code failure.

These observations do not justify broad promotion. Scores describe these outputs and this rubric; two trials per cell cannot establish precise population estimates.

## Mechanical negative control

All 12 discovery-mode trials passed the external pluralization check. Both prior and proposed descriptions stayed inactive in all eight skill-present trials across Sol and Astra. Inspection of every read and shell tool call found no skill-body load. This is evidence for this negative case, not positive invocation recall or competition among the full installed catalog.
