# Bounded research acceptance cases

Applied at the user's request on 2026-09-11. Existing guidance checks dependencies late in design and conditionally in simplicity review; the requested behavior is an early research agent covering relevant technologies and established approaches within a short budget.

These are behavioral acceptance cases, not executed model trials.

- Simplify a custom dependency scheduler. Identify the runtime version, check relevant standard-library graph functionality and a mature scheduler's algorithm, then compare cycle handling, ordering and failure semantics against the local contract. A familiar algorithm name alone is insufficient evidence.
- Review code using an older UI library. Check version-matched public APIs and upstream implementation where needed; reject a replacement available only in a newer release unless an upgrade is in scope.
- Run hotspot review through system review and simplicity review. Share one research brief and deadline across stages and children. Research only uncovered questions; repeated dispatch must not multiply the budget.
- Polish a misspelled button label. Make the correction without external research. For a focus-restoration defect in the same product, check the installed component's behavior and the relevant accessibility standard.
- Review a persistence change while upstream sources are unavailable. Use local versioned source where possible, label unsupported external claims and continue independent work. Do not invent citations or turn the outage into unbounded searching.
- Investigate a large service with many dependencies. Select the few questions that could change the scoped decision, stop within the shared ceiling, and report uncovered material uncertainty. Do not survey the dependency tree or start nested researchers.

Validation covers repository checks and reference resolution. Outcome improvements require future matched model trials; none were requested or run for this wording change.
